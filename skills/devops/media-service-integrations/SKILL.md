# Media Service Integrations

This skill covers configuring and troubleshooting media service integrations (primarily Spotify) on Hermes Agent, with special attention to containerized/Umbrel environments where OAuth callbacks and network access require workarounds.

## Spotify Integration

### Prerequisites
- Spotify Developer App created at https://developer.spotify.com/dashboard
- Redirect URI: `http://127.0.0.1:43827/spotify/callback` (default Hermes port)
- Spotify Premium required for playback control (play, pause, skip, volume, transfer)

### Authentication on Umbrel/Container

**Problem**: The OAuth callback runs on `127.0.0.1:43827` inside the container, but the browser runs on the host machine. The callback fails with "cannot connect to server".

**Solution**: Manual PKCE flow with token injection.

```bash
# 1. Get authorization URL (run in Hermes container)
hermes auth spotify login --no-browser --client-id YOUR_CLIENT_ID

# 2. Copy the printed URL, open in host browser, authorize
# 3. Copy the `code` parameter from the failed redirect URL:
#    http://127.0.0.1:43827/spotify/callback?code=AQBxxx&state=...

# 4. Exchange code for tokens using the PKCE verifier
#    (The verifier is generated by Hermes but lost on timeout)
#    Use the helper script below with a known verifier.
```

**Helper Script** (`scripts/spotify_pkce.py`):
```python
#!/usr/bin/env python3
# Manual PKCE token exchange for containerized Hermes
# Usage: python3 spotify_pkce.py <auth_code> <code_verifier>
```

After obtaining tokens, inject into `/opt/data/auth.json`:
```python
# Update auth.json directly
spotify_state = {
    'access_token': '...',
    'refresh_token': '...',
    'expires_at': '2026-06-21T22:08:04.986231+00:00',
    'scope': '...',
    'client_id': '...',
    'redirect_uri': 'http://127.0.0.1:43827/spotify/callback',
    'api_base_url': 'https://api.spotify.com/v1',
    'auth_type': 'oauth_pkce',
}
```

### Token Refresh
Tokens auto-refresh on 401. Manual refresh:
```bash
curl -X POST https://accounts.spotify.com/api/token \
  -d grant_type=refresh_token \
  -d refresh_token=REFRESH_TOKEN \
  -d client_id=CLIENT_ID
```

### Playback Control
- Device must be active (Spotify open on device)
- Echo/Alexa devices appear as Spotify Connect speakers: `device_id` format: `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx_amzn_1`
- Transfer: `spotify_devices transfer --device_id <id>`
- Play: `spotify_playback play --uris spotify:track:... --device_id <id>`

### Playlist Management - Known Limitation
Creating playlists works (`POST /me/playlists`), but **adding tracks returns 403 Forbidden** even with `playlist-modify-private` and `playlist-modify-public` scopes. This appears to be an API/app permission issue with the Hermes Spotify app registration.

**Workaround**: Create playlist via API, then add tracks manually in Spotify app using "Recommended" suggestions.

## Groq as Custom Provider

Groq is not a built-in provider but works via `custom_providers` in `config.yaml`:

```yaml
custom_providers:
  - name: groq
    base_url: https://api.groq.com/openai/v1
    key_env: GROQ_API_KEY

model:
  default: llama-3.3-70b-versatile
  provider: custom:groq
```

Add `GROQ_API_KEY` to `.env`. Switch at runtime:
```
/model custom:groq:llama-3.3-70b-versatile
```

**Note**: Groq models have limited function calling support. For tool-heavy workflows, prefer models with better tool calling (Together AI, OpenRouter) or disable tools for Groq sessions.

## Troubleshooting

| Issue | Cause | Fix |
|-------|-------|-----|
| OAuth callback fails | Container localhost ≠ host | Use manual PKCE flow (see above) |
| 403 on playlist add | App permissions / API bug | Manual add in Spotify app |
| 403 Forbidden on playback | No active device | Open Spotify on target device first |
| Groq tool calling fails | Model limitation | Use simpler prompts or different model |
| Token expired | 1hr expiry | Auto-refresh works; manual refresh via token endpoint |
